# Session schedule and moderator script — PRIVATE

## Unscored pilot: 60 minutes

| Minutes | Activity |
|---|---|
| 0–5 | Explain unscored rehearsal, tool rules and optional recording; record experience |
| 5–15 | Practice r-450; demonstrate file selection and answer submission, not defect diagnoses |
| 15–30 | P00 period 1, usual tools; timer includes file opening and response |
| 30–33 | Collect response; switch to fresh workspace; no answer feedback |
| 33–48 | P00 period 2, usual tools plus Pebbles |
| 48–60 | Debrief loading, interpretation, time cap, instructions and scoring ambiguity |

Say: “We are testing the materials and workflow, not your performance. Tell me when instructions or tools are unclear. The packet may or may not contain a discrepancy.” Use light concurrent narration for the pilot only; it changes timing and is not speed evidence. Rehearse scoring afterward. Log where the participant hesitated and the exact wording involved.

## Scored session: approximately 90 minutes

5-minute introduction, 8-minute standard practice, four 15-minute tasks, approximately 4 minutes total transitions, 10-minute retrospective debrief (87 minutes plus buffer). Use session-schedule.csv. Show only each current task. Use silent timed work rather than think-aloud; retrospective questions follow all four tasks.

Start timer when the task and files become available. Say: “Investigate the claim and submit your evidence and conclusion using the template. You have 15 minutes.” At timeout: “Please submit your current response.” For interpretation requests: “Please use your judgment and explain your uncertainty.” For tool failure: record time and action; do not coach the diagnosis.

Debrief: What took the most work? Which evidence changed your view? What did you trust without checking? What did the explanation leave unclear? Did you recognize the dataset or case? What would you need before using this on your own work?

## Pilot exit checklist

- Both conditions can access the same packet evidence; Pebbles loads all seven files.
- Participant understands the target claim versus auxiliary reference readout.
- No answer keys, case families, past runs or example gallery are exposed.
- Timer, submission capture, scoring and results entry work.
- Log any case-difficulty mismatch, learning effect, rubric disagreement or unexpected UI explanation.
- Save issues with owner, proposed change and resolution; freeze the revised version before scored work. A pilot that finds unresolved problems is useful, not a successful efficacy study.
